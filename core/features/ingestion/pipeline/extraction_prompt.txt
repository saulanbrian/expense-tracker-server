### Critical Document Classification Rule:
First, analyze the document's visual structure.

- Determine if it is a financial billing document (e.g., invoice, receipt, utility bill, statement of account, purchase order).
- If it is NOT a billing document (e.g., it's a menu, contract, passport, ID, or unrelated image), you must set "is_financial_billing" to false, set "document" to null, and set "document_line_items" to null or empty. Do NOT try to extract data from invalid files.
- If it IS a billing document, set "is_financial_billing" to true and proceed with full extraction.

### Date Rules
- ALL dates MUST be in YYYY-MM-DD format (e.g., "2024-10-26")
- If you see 10/26/2024 or 26/10/2024, convert to 2024-10-26
- If you see October 26, 2024, convert to 2024-10-26
- Return null for missing or unreadable dates

### Data Rules & Fallbacks (Only if is_financial_billing is True):
1. "document.vendor_name", "document.currency", and "document.total_amount" are highly critical. If they cannot be found or confidently inferred, return null for those specific fields.
2. For "document.currency", always output standard 3-letter ISO codes (e.g., USD, EUR, GBP, PHP).
3. Dates ("invoice_date", "due_date") must use strict YYYY-MM-DD format. Return null if missing or unreadable.
4. For "document_line_items":

   - If "quantity" is missing but a price exists, default it to 1.
   - If "unit_price" is missing, default it to equal the item's "total_price".
5. "gl_code": Based on the line item "description", intelligently predict a standard corporate accounting category code (e.g., SOFTWARE_SAAS, OFFICE_SUPPLIES, TRAVEL_MEALS, HARDWARE_EQUIPMENT, UTILITIES, UNCLASSIFIED).

### Mathematical Integrity:
- The sum of all item "total_price" values MUST equal the parent "subtotal".
- The "subtotal" + "tax_amount" MUST equal the parent "total_amount".
- If the document contains conflicting numbers due to print layouts, prioritize the explicitly stated grand "total_amount" on the document and adjust line item details to fit cleanly.
